# 演示视频制作标准

> **一套把「HTML 页面」做成「汇报级演示视频」的完整方法。**
> 适用于：方案汇报、产品演示、概念讲解等**以讲解为主、需要精确控制画面与旁白**的短片（30 秒 ~ 3 分钟）。
> 本文档可直接作为 SKILL 的参考材料，也可照着从零复现。
>
> **配套工具包见 [`工具/`](./工具/) —— 含最小可运行模板与全部脚本。**
> 该工具包已做过端到端验证：用模板从零出一支 3 幕 23.8 秒的片子，
> 画面、分段字幕推进、音量（mean −20.3 dB / max −4.2 dB）全部达标。

---

## 一、这套方法的定位

### 适合什么

| 场景 | 适合度 |
|---|---|
| 汇报里插一段 1~3 分钟的讲解视频 | ✅ 最合适 |
| 需要旁白与画面**逐句对齐** | ✅ 最合适 |
| 内容经常改（改一句话就要重出片） | ✅ 脚本化，重出成本低 |
| 一页页的图示、流程、数据看板 | ✅ 最合适 |
| 实拍素材、人物出镜、复杂特效 | ❌ 不适合，请用剪辑软件 |

### 为什么不用剪辑软件

用 AE / 剪映 / Premiere 做这类片子，有三个绕不开的痛点：

1. **改一句话要重新对轴** —— 旁白改了，字幕、画面节奏、转场全要手动挪
2. **画面元素无法复用** —— 想把网页上的图表搬进视频，只能截图，一改就得重截
3. **无法版本化** —— 14 个版本的视频，谁也说不清两版之间改了什么

这套方法把视频变成**代码的产物**：改台词改一行，重出即可；画面就是网页，改 CSS 就改画面；两版差异 `diff` 一下就知道。

### 核心取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 画面载体 | **单文件 HTML** | 自包含、可浏览器打开、改样式即改画面 |
| 动画定位 | **Web Animations API** | 可被 `__seek(t)` 逐帧精确定位（这是录屏能对齐的关键）|
| 录屏方式 | **CDP 逐帧截图** | 不用屏幕录制，避免掉帧、鼠标、通知干扰 |
| 字幕 | **烧入画面** | 汇报电脑不装字体也不会错位；同时导出 SRT 供二次剪辑 |
| 编码 | **H.264 + AAC** | 会议电脑兼容性优先（HEVC 在很多 Windows 上放不出来）|

## 二、技术链路总览

```
① 单文件 HTML 演示页（1920×1080，逐幕 .scene，每幕带 data-dur / data-vo）
        │
        ├─► ② 解析时间轴 → 逐幕 TTS 合成 → 逐幕 mp3
        │        │
        │        └─► ③ 拼接人声轨 + loudnorm 归一化 → mix.wav
        │
        ├─► ④ headless Chrome + CDP，按 __seek(t) 逐帧截图 → frames/f00001.jpg …
        │
        ├─► ⑤ 生成 SRT（从时间轴 + data-sub 导出）
        │
        └─► ⑥ ffmpeg 合成：frames + mix.wav + 淡入淡出 → H.264/AAC 成片
                 │
                 └─► ⑦ 派生 1.2 倍速版（setpts + atempo）
```

**一句话**：页面负责"长什么样"，脚本负责"什么时候说什么、画面走到哪一帧"。

## 三、页面编写规范（最核心）

### 3.1 文件结构

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>…</title>
  <style>/* 全部样式内联，单文件自包含 */</style>
</head>
<body class="video-mode">
<div id="stage"><div id="deck">

  <section class="scene light v1s1 active"
           data-dur="10.2"
           data-vo="这一句是要被念出来的旁白"
           data-sub="这一句是字幕（通常与 data-vo 相同）">
    <div class="wrap"><!-- 这一幕的画面 --></div>
  </section>

  <section class="scene light v1s2" data-dur="8.5" data-vo="…" data-sub="…">
    <div class="wrap">…</div>
  </section>

</div></div>

<div id="vsub"><div class="box" id="vsubtext"></div></div>

<script>/* __seek 机制，见 3.4 */</script>
</body>
</html>
```

### 3.2 逐幕属性（四个）

| 属性 | 作用 | 必填 |
|---|---|---|
| `data-dur` | 这一幕的**总时长（秒）**，决定录屏帧数和字幕时间轴 | ✅ |
| `data-vo` | 旁白文本，送 TTS 合成 | ✅ |
| `data-sub` | 字幕文本，烧入画面并导出 SRT | ✅ |
| `data-subs` | **幕内分段字幕**，见 3.6 | 可选 |
| `data-say` | 旁白的"读法覆盖"（如把 `500kV` 读成「五十万伏」）| 可选 |

### 3.3 时长公式（必须遵守）

```
data-dur = LEAD + TTS时长 + TAIL
```

推荐 `LEAD = 0.30s`、`TAIL = 0.60s`（留出画面入场和收尾）。

**关键做法：先测后填，不要估。**

```python
# 改台词后，先量出真实 TTS 时长，再决定 data-dur
dur = tts_duration(text)             # 实际合成一次，ffprobe 量时长
scene_dur = round(0.30 + dur + 0.60, 1)
```

**语速经验值**（腾讯云 502005 解说男声，Speed 0）：

| 语速档 | 每秒字数 | 感受 |
|---|---|---|
| Speed −2 | ≈ 3.4 字/秒 | 慢，适合庄重场合 |
| Speed −1 | ≈ 4.3 字/秒 | 偏慢 |
| **Speed 0** | **≈ 5.3 字/秒** | **默认，有力度** |
| Speed 1 | ≈ 6.6 字/秒 | 偏快，适合短句密集的片子 |

> ⚠️ **不要靠"加快语速"来压缩时长**。实测压到 2 分钟以内，靠的是**改短句子**（738 字 → 482 字），而不是调 Speed。语速一提，听感立刻变"赶"。

### 3.4 动画机制（录屏能对齐的关键）

**所有入场动画必须写成这样：**

```html
<div class="au" style="--d:0.72s">内容</div>
```
```css
.scene.play .au { animation: au .78s cubic-bezier(.2,.7,.3,1) both;
                  animation-delay: var(--d, 0s); }
@keyframes au { from { opacity: 0; transform: translateY(34px); } }
```

**为什么必须这样**：录屏引擎靠 `__seek(t)` 定位每一帧，它的实现是

```js
window.__seek = function(t){
  // 1. 算出 t 落在第几幕、幕内时间 local
  // 2. 切换场景的 .active / .play
  // 3. 把这一幕里所有动画「暂停」，并把 currentTime 设成 local*1000
  var anims = cur.getAnimations({subtree: true});
  for (var i = 0; i < anims.length; i++){
    anims[i].pause();
    anims[i].currentTime = local * 1000;   // ← 逐帧定位就靠这句
  }
};
```

`getAnimations()` 能拿到 **CSS animation**，但**拿不到 JS 定时器、setTimeout、transition 的一部分情况**。

**所以：**

| 写法 | 能否被逐帧定位 |
|---|---|
| `animation-delay: var(--d)` + CSS animation | ✅ 可以 |
| CSS transition（由类切换触发）| ⚠️ 部分可以，容易错位 |
| `setTimeout` / `requestAnimationFrame` | ❌ **不行** |
| `video` 元素 | ❌ 不行 |

> **一句话：入场动画一律用 CSS animation + `animation-delay`，时间写在 `--d` 上。**

### 3.5 动画门控（必踩的坑）

动画要**只在该幕播放时**才跑。门控选择器必须写成**同一个元素上的多个类**：

```css
/* ✅ 正确：section 同时有 scene / play / v1s2 三个类 */
.scene.play.v1s2 .card { animation: up .7s both; animation-delay: var(--d); }

/* ❌ 错误：被解析成「.v1s2 的祖先里有 .scene.play」，不生效 */
.scene.play .v1s2 .card { … }
```

### 3.6 幕内分段字幕（长旁白必须用）

**问题**：默认一幕一条字幕。若某幕旁白有 100 多字，底部会停着一块 3 行的字幕十几秒不动，又长又不跟着说话走。

**做法**：给该幕加 `data-subs`，格式 `幕内秒数|文本`，用 `;;` 分隔：

```html
<section class="scene light v8s0" data-dur="19.7"
  data-vo="电力安全生产作业，流程环环相扣、控制步步到位、过程全面闭环。安全监督着重捕捉……"
  data-sub="（同 data-vo）"
  data-subs="0.30|电力安全生产作业，流程环环相扣、控制步步到位、过程全面闭环。
         ;;5.58|安全监督着重捕捉过程中的问题和薄弱环节 ——
         ;;8.97|人员不规范行为、物的不安全状态、管理漏洞。
         ;;12.41|过程严谨透明、规章完整、制度健全，
         ;;15.08|但大量重复的检索、识别、判定，靠人做不完。">
```

**配套三处改动**（缺一不可）：

1. **页面 JS** 加 `subAt(sc, local)`，在 `__seek` 里每帧调用：

```js
function subAt(sc, local){
  var spec = sc.getAttribute('data-subs');
  if (!spec) return subOf(sc);                       // 没配就退回整幕一条
  var segs = spec.split(';;'), txt = '';
  for (var i = 0; i < segs.length; i++){
    var b = segs[i].indexOf('|');
    if (b < 0) continue;
    if (local >= parseFloat(segs[i].slice(0, b))) txt = segs[i].slice(b + 1);
  }
  return txt || subOf(sc);
}
```

2. **SRT 导出**同步拆条（否则外挂字幕和画面里烧的对不上）

3. **字幕条加最小宽度**（否则 `inline-block` 会按内容收缩，分段推进时**条宽来回跳**）：

```css
#vsub .box { min-width: 940px; }
```

**每段的时间怎么定**：按标点把旁白切句，**逐句单独送 TTS 量时长**，再按整段实测时长等比缩放。比按字数估算准得多（实测误差 < 0.1 秒）。

### 3.7 样式组织

页面变大后，样式要分文件，**按"版本"或"幕组"拆**：

```
build/
  base.css      ← 基础骨架（.wrap / .s-topbar / .stage）
  v1.css        ← 第一批幕的样式
  v2.css        ← 第二批
  v8.css        ← 某一幕专用（全部规则加 .v8s0 前缀）
```

> ⚠️ **不要把 CSS 直接写进 Python 的 f-string 模板**。f-string 会把 `{` `}` 当成表达式，
> `background:{...}` 之类的写法直接报 `NameError`。**写成独立 `.css` 文件再读进来拼接。**

**每条样式都要带作用域前缀**（`.v8s0 .card{…}`），避免污染其他幕。

### 3.8 视觉一致性

| 规范 | 要求 |
|---|---|
| 画布 | 固定 `1920×1080`，内容区留白 `padding: 96px 130px 118px` |
| 底部安全区 | 字幕条在 `bottom: 34px`，**正文内容底部不要低于 y≈900px**，否则被字幕条压住 |
| 配色 | 用 CSS 变量统一（`--l-ink` / `--l-acc` / `--l-line` …），禁止散写色值 |
| 图标 | **一律内嵌 SVG，禁止 emoji**（见坑 #3）|
| 字号 | 主标题 52–64px，小节标题 26–32px，卡片标题 24–28px，说明文字 15–18px，正文最小 14px |

## 四、配音规范

### 4.0 三档 provider（默认自动选择）

**同一句话实测**：腾讯云 3.49s ｜ edge 5.26s ｜ say 5.16s —— **语速口径不同，腾讯云明显更快**。

| provider | 需要密钥 | 依赖 | 音质 | 备注 |
|---|---|---|---|---|
| `tencent` | ✅ | 无（纯标准库） | **最好** | 正式交付 |
| `edge` | ❌ 免密钥 | 一键自建 venv | 好 | 微软 Edge 在线语音，跨平台（**推荐默认**）|
| `say` | ❌ 免密钥 | 无（macOS 自带） | 一般 | **零配置兜底** |

`TTS_PROVIDER=auto`（默认）按 tencent → edge → say 顺序取第一个可用的，**并明确打印用了哪个**。

**换 provider 后不用手工重校时长** —— `make.sh` 发现某幕旁白装不下时，会**自动延长该幕**，
并生成 `*-fit.html` 用于录屏（**不改源文件**）。加 `STRICT=1` 可改为报错退出。

推荐音色见 `scripts/synth.py` 的 `VOICES`；用 `VOICE=xxx` 指定，`SPEED=n` 调语速。


### 4.1 TTS 参数

```python
VOICE_ID = "502005"   # 腾讯云音色ID：解说男声（超自然大模型）
SPEED    = 0.0        # 语速：0 ≈ 5.3 字/秒
```

常用音色（腾讯云）：

| ID | 音色 | 适合 |
|---|---|---|
| `502005` | 智小解 · 解说男声 | **主旁白（默认）** |
| `502003` | 智小敏 · 聊天女声 | 女性角色 |
| `603006` | 沉稳青叔 · 男 | 领导/专家角色 |
| `603007` | 邻家女孩 · 女 | 年轻角色 |
| `603005` | 知心大林 · 男 | 叙述角色 |
| `602005` | 专业梓欣 · 女 | 专业角色 |

### 4.2 多角色配音

如果需要"不同角色不同声音"（如数字分身轮流说话），把音色做成表，按角色查：

```python
CAST = {
  "officer": "502005",   # 数字安全员
  "s1":      "502003",   # 计划环节分身
  "s3":      "603006",   # 勘察环节分身
  "sum":     "502005",   # 总结
}
```

> **同一角色全片固定音色** —— 观众靠音色认人，换一次就乱。

### 4.3 音轨归一化

逐幕 mp3 拼成整条人声轨后，**必须做响度归一化**，否则各句音量不齐：

```bash
ffmpeg -i voice.wav \
  -af "loudnorm=I=-16:TP=-1.5:LRA=11,alimiter=limit=0.97" \
  mix.wav
```

**验收基线**：`mean_volume ≈ −20 dB`、`max_volume ≈ −4 ~ −1.5 dB`

```bash
ffmpeg -i mix.wav -af volumedetect -f null /dev/null 2>&1 | grep volume
```

### 4.4 凭证管理

TTS 密钥**不要硬编码**。推荐从环境变量或独立 `.env` 读：

```python
ENV_PATH = os.environ.get("TTS_ENV", os.path.expanduser("~/.config/live-video/.env"))
```

> ⚠️ 含密钥的 `.env` **不可外发**。交付外部时替换为对方自己的腾讯云 TTS 子账号密钥。
> 若不改配音，直接把 `05_配音/` 里现成的音轨随包交付即可（对方无需任何凭证）。

## 五、录屏规范

### 5.1 原理

`capture.js` 通过 **CDP（Chrome DevTools Protocol）** 连接 headless Chrome：

```
启动 Chrome(headless) → 打开页面 → 等 __seek 就绪
  → 对每一帧：__seek(t) → Page.captureScreenshot → 存 jpg
```

**为什么不用屏幕录制**：屏幕录制会受帧率抖动、鼠标、通知、系统动画影响；逐帧截图则是**确定性**的 —— 同样输入必然得到同样输出。

### 5.2 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| 分辨率 | `1920×1080` | 固定 |
| 帧率 | **25fps** | 中文讲解足够；30fps 只增体积 |
| 截图格式 | `jpeg`，`quality: 95` | 比 png 小 10 倍，画质足够 |
| 缩放因子 | `--force-device-scale-factor=1` | 防止 Retina 出 2x 图 |
| 其他 | `--headless=new --disable-gpu --hide-scrollbars --disable-lcd-text` | |

### 5.3 启动前必须确认

```js
const r = await evaluate('typeof window.__seek === "function" && !!document.querySelector(".scene.active")');
if (!r) throw new Error('页面未就绪（未找到 __seek）');
```

**不要用固定 `sleep` 等页面加载** —— 页面复杂度不同，加载时间不同。要**轮询检查就绪标志**。

### 5.4 辅助工具

| 脚本 | 用途 |
|---|---|
| `capture.js` | 全片逐帧抓取（出片用）|
| `stills.js` | 按时刻列表抓静帧（**核画面用，最常用**）|
| `shot_static.js` | 静态页（非逐幕页）整页截图，可指定等待毫秒 |

> **`stills.js` 是日常改图时的主力**：改完一页，抓 3~5 个时刻看一眼，不用出整片。

> ⚠️ 静态页截图要**等动画播完**（`shot_static.js` 最后一个参数是等待毫秒）。默认 1500ms 对慢速入场动画不够，建议 3500~4000ms。

## 六、字幕规范

### 6.1 烧入 + 外挂，双份

| 形式 | 用途 |
|---|---|
| **烧入画面** | 汇报现场直接放，不依赖播放器字幕功能；换电脑不会错位 |
| **外挂 SRT** | 交给后期二次剪辑用 |

**两者必须同源**：都从时间轴 + `data-sub` / `data-subs` 生成，禁止手工维护两份。

### 6.2 字幕条样式

```css
#vsub { position: fixed; left: 50%; bottom: 34px; transform: translateX(-50%);
        max-width: 1760px; width: 1760px; text-align: center; }
#vsub .box { display: inline-block;
             background: rgba(6,24,16,.84); color: #F2FBF6;
             border-radius: 12px; padding: 12px 30px;
             font-size: 26px; line-height: 1.45;
             white-space: normal; max-width: 1560px;
             min-width: 940px;          /* ← 关键：防止分段推进时宽度跳 */
             }
```

### 6.3 单条字幕的长度上限

| 项 | 建议值 |
|---|---|
| 单条字数 | **≤ 30 字**（一行） |
| 单条时长 | **≤ 6 秒** |
| 超出怎么办 | 用 `data-subs` 拆成分段字幕 |

### 6.4 换行策略

`white-space: normal` + `max-width`，让浏览器自动换行。
**不要用 `nowrap`** —— 长句会被裁掉。

## 七、编码与交付规范

### 7.1 编码参数

```bash
ffmpeg -framerate 25 -i frames/f%05d.jpg -i mix.wav \
  -filter_complex "[0:v]fade=t=in:st=0:d=0.9:color=white,\
                   fade=t=out:st=${FO}:d=1.4:color=white,format=yuv420p[v]" \
  -map "[v]" -map 1:a \
  -c:v libx264 -preset slow -crf 18 -profile:v high -level 4.1 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -ar 44100 -ac 2 \
  -shortest -movflags +faststart out.mp4
```

| 参数 | 值 | 理由 |
|---|---|---|
| 编码器 | **H.264**（不用 HEVC）| 会议电脑 / U 盘播放兼容性优先 |
| CRF | 18 | 视觉无损，体积可接受 |
| Profile | high / level 4.1 | 兼容老设备 |
| 像素格式 | `yuv420p` | 必须，否则部分播放器黑屏 |
| 音频 | AAC 192k / 44.1kHz / 立体声 | |
| 淡入淡出 | **白场** 0.9s 进 / 1.4s 出 | 与页面白底一致，衔接自然 |
| `+faststart` | 必须 | 支持边下边播 |

### 7.2 派生版本

**1.2 倍速版**（音高不变，用于"必须在 2 分钟内"的场合）：

```bash
ffmpeg -i in.mp4 \
  -filter_complex "[0:v]setpts=PTS/1.2[v];[0:a]atempo=1.2[a]" \
  -map "[v]" -map "[a]" \
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -c:a aac -b:a 192k \
  -movflags +faststart out.mp4
```

> `atempo` 保持音高；`setpts` 同步画面。**两者倍率必须一致**，否则音画不同步。

**字幕也要按同倍率重算时间轴**：

```python
new_time = old_time / 1.2
```

### 7.3 交付矩阵

正式交付一般出 **4 个版本**：

| 版本 | 用途 |
|---|---|
| 含字幕 · 1.0x | **主交付** |
| 无字幕 · 1.0x | 二次剪辑用（想自己配字幕）|
| 含字幕 · 1.2x | 时间紧张的场合 |
| 无字幕 · 1.2x | 同上 + 二次剪辑 |

### 7.4 多片拼接（插入/替换某一段）

**场景**：已有 A、B 两段，要把素材 C 插在中间。

**不要**整片渲完再从中间切开 —— 要么按关键帧对齐（切点不准），要么二次编码（损画质）。

**正确做法**：A、B 分别渲染，与 C 直接拼接：

```bash
# 三段必须同码同帧率同分辨率
printf "file '%s'\n" "$(pwd)/A.mp4" "$(pwd)/C.mp4" "$(pwd)/B.mp4" > concat.txt
ffmpeg -f concat -safe 0 -i concat.txt -c copy -movflags +faststart out.mp4
```

**零二次编码，接缝精确。**

> ⚠️ 拼接前必须确认三段**编码参数完全一致**。
> 曾经踩过：主片是 H.264/25fps，素材是 HEVC/30fps，`-c copy` 直接失败。要么统一转码，要么重出。

## 十、踩坑清单（重要）

按"被发现时的代价"排序，**前 5 条建议直接写进 SKILL 的强制约束**。

### 🔴 致命级

**#1 入场动画用了 JS 定时器 → 录屏完全对不上**
`__seek(t)` 只能暂停/定位 CSS animation。用 `setTimeout`、`requestAnimationFrame`、`<video>` 的动画**无法被逐帧定位**，录出来会闪烁或停在错误状态。
→ **一律用 CSS `animation` + `animation-delay: var(--d)`。**

**#2 门控选择器写成三层 → 动画永不触发**
```css
.scene.play .v1s2 .card { }   /* ❌ 不生效 */
.scene.play.v1s2 .card { }    /* ✅ 正确 */
```
分开写会被解析成"后代"，而 `.scene` 和 `.v1s2` 是**同一个元素上的两个类**。

**#3 emoji 当图标 → 不同系统渲染不一致**
macOS 上是彩色 emoji，Windows/Linux 上可能变黑白方块，甚至不显示。
→ **所有图标内嵌 SVG**，用 `stroke="currentColor"` 继承容器配色（一套图标适配多档颜色）。

**#4 CSS 写进 Python f-string → `NameError`**
f-string 模板里的 `{` `}` 会被当表达式，`background:linear-gradient(...)` 直接报错。
→ **CSS 一律写成独立 `.css` 文件**，读进来拼接。

**#5 渲染失败被 `|| true` 吞掉 → 交付残缺视频**
```bash
bash make.sh 2>&1 | grep xxx || true     # ❌ make.sh 失败了也不知道
```
TTS 接口偶发失败会让 `make.sh` 中途退出，但管道 + `|| true` 把退出码吃了，脚本继续往下跑，最后产出一个**缺了某一段的视频**。
→ **渲染要加"产物校验 + 重试"**：
```bash
render() {
  for try in 1 2 3; do
    bash make.sh ... || true
    [ -s "$out" ] && return 0          # 产出文件存在才算成功
    sleep 3
  done
  return 1
}
# 拼接前再校验一次所有分段都在
for f in A.mp4 B.mp4 C.mp4; do [ -s "$f" ] || { echo "缺少 $f"; exit 1; }; done
```

**#6 `curIdx` 初始化为 0 → 第一幕内容永不显示**
`__seek` 靠「当前幕号变了」才执行切幕（切 `.active`/`.play`）。若 `curIdx` 初始值写成 `0`，
那么 `t=0` 时 `idx === curIdx`，**切幕分支被跳过 → `.play` 类加不上 → 该幕动画不触发 → 内容永远是 `opacity:0`**。
表现为：**只有第一幕是空白的，后面几幕全部正常**（因为后面都会换幕）。
→ **`curIdx` 必须初始化成 `-1`。**（原页面就是 `-1`，抄代码时容易顺手写成 0）

### 🟠 高代价级

**#7 用 mtime 判断"要不要重跑" → 白跑**
重新生成了页面但内容没变，mtime 变了，脚本白跑一遍渲染（几分钟）。
→ **比内容哈希**：`[ "$(cat "$out.md5")" = "$(md5 -q "$html")" ]`。

**#8 幕数少于一屏就被拒绝渲染**
某段只有 3~4 幕时，脚本里的 `assert len(scenes) >= 6` 直接失败。
→ 这个检查本意只是**防止解析到错误页面**，真正的校验应该是 `幕数 == data-dur 个数`。**下限要放宽到 1。**

**#9 字幕条宽度随内容跳**
`inline-block` 的盒子按内容收缩。幕内分段字幕推进时，每段长度不同 → 条宽来回跳，很廉价。
→ 加 `min-width`。

**#10 指示箭头指向了空白**
用"等分格子"摆三个箭头（`grid-template-columns: repeat(3,1fr)`），却让它们指向一个**宽度不同、居中的元素**。
实测：面板通栏 1660px，箭头在 x=257/790/1323，而目标胶囊只有 432px 宽（574–1006）—— **左右两个箭头各偏 300 多像素**。
→ 改成**"汇总横线 + 居中单箭头"**：三个支线汇到一条横线，再由居中的单箭头落到目标。几何上必然对齐，且不依赖任何尺寸假设。

**#11 底部内容被字幕条压住**
字幕条固定在 `bottom: 34px`。正文排得太满时，最下面的元素会被压住（而且**在编辑器里看不出来**，只有出片才发现）。
→ **正文内容底部不要低于 y≈900px**，出片前必须抽帧核对。

**#12 交付/演示了旧版本**
工作区改完，交付包里是上次同步的旧文件 —— 打开一看"怎么和你说的不一样"。
→ **同步后必须做一次内容核对**（md5 或渲染验证），且**验证要针对交付包里的文件**，不能拿工作区的结果冒充。

### 🟡 效率级

**#13 `timeout` 命令 macOS 上没有**
写 `timeout 60 find …` 会静默失败（`command not found` 被 `||` 吃掉）。
→ 用 `gtimeout`（`brew install coreutils`）或改用 `&` + `sleep` + `kill`。

**#14 Python `%` 格式化撞上中文全角括号**
文档模板里出现 `）` 时，`"…%" % x` 会报 `unsupported format character`。
→ 用 `str.replace('__占位符__', 值)` 代替 `%`。

**#15 用 `grep` 查二进制视频的字符串**
mp4 里会偶然出现目标字节（如 `V11` 出现在 SVG 路径 `-19V11z` 里），产生假阳性。
→ 限定 `--include="*.py" --include="*.html"` 等文本类型。

**#16 静态页截图抓早了**
页面有 1.8 秒的入场动画，默认等 1500ms 截图 → 后出现的元素还没出来。
→ 等动画播完再截（3500~4000ms），或先强制把动画设到终态。

**#17 帧缓存占满磁盘**
`build/frames/` 逐帧 jpg，一部 2 分钟片子约 3000 帧，几百 MB 到 1 GB。
→ 目录名标 `_缓存-可删`，出片后可随时删。

**#18 shell 变量后面紧跟中文全角字符 → 变量名被吞**
```bash
echo "未配置（$ENVF）"     # ❌ bash 把「）」当成变量名的一部分 → unbound variable
echo "未配置（${ENVF}）"   # ✅ 加花括号明确边界
```
中文、日文等全角标点紧跟 `$VAR` 时，bash 会把全角字符一并纳入变量名。
→ **变量后面只要不是 ASCII 字母数字下划线，一律写 `${VAR}`。**

### 出片前自检清单

- [ ] 每一幕都抽帧看过（`stills.js` 逐幕核对）
- [ ] 正文底部没有被字幕条压住
- [ ] 首尾淡入淡出正常
- [ ] 音量检测：`mean ≈ −20dB` / `max ≥ −5dB`
- [ ] 字幕与旁白**逐句对得上**（抽 3 处核对）
- [ ] 拼接片校验过所有分段文件存在
- [ ] 交付包内容与工作区一致（md5）
- [ ] 1.2 倍速版音画同步

## 十一、节奏经验值

### 时长预算

| 场合 | 建议时长 | 字数上限（Speed 0）|
|---|---|---|
| 现场播放的插片 | 60~90s | ≈ 320~480 字 |
| 汇报主线片子 | 120~180s | ≈ 640~950 字 |
| 完整讲解 | 180~300s | 按需 |

**字数估算公式**：`字数 ≈ (目标秒数 − 幕数 × 0.9) × 5.3`

例：目标 90 秒、14 幕 → `(90 − 12.6) × 5.3 ≈ 410 字`

### 单幕节奏

| 项 | 建议 |
|---|---|
| 单幕时长 | 4~20 秒（超 20 秒要拆幕，或加幕内分段字幕）|
| 单句字数 | **15~35 字**（超过 50 字就该拆）|
| 幕间过渡 | 白场叠化 0.55s |

### 压缩时长的正确顺序

1. **砍内容** —— 删掉与别幕重复的、和主题无关的
2. **拆短句** —— 「A，B，C」的长复句 → 「A、B、C」的并列短句
3. **去铺垫** —— 删「此外」「正因如此」「让我们来看」这类连接语
4. **合并同义** —— 几句话说同一件事，留最有力的一句
5. ~~提高语速~~ —— **最后才考虑，且尽量不用**

## 附：本方法的边界

**它擅长**：把**结构化的信息**（流程、数据、对比、时间轴）做成**节奏精确**的讲解视频。

**它不擅长**：
- 实拍素材、真人出镜
- 复杂三维动画（CSS 3D 只能做到轻量透视）
- 需要逐帧手 K 的运动图形
- 超过 5 分钟的片子（页面会变得难以维护，建议拆成多支）

**一条经验**：**画面越"像一页 PPT"，这套方法越省力。**
如果发现某一幕怎么排都不好看，通常不是技术问题，而是**这一幕想说的信息太多** —— 拆成两幕。
